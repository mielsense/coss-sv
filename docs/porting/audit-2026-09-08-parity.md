# Component parity audit, 2026-09-08

## Source coverage

The audit read each production wrapper, helper, public type, and export listed below, then compared
it with the complete permitted registry source. The reference revision is
`19620ae8cae81e30775f2cde03829326cb4916b2`; Shards is
`f8b134dfa627cbe3da7e538e2531b0b9fce4d48e`. No excluded COSS package source was used.

For each family, registry means `reference/apps/ui/registry/default/ui/<family>.tsx` and docs means
`reference/apps/ui/content/docs/components/<family>.mdx`. All 17 available documentation pages
were read. Sidebar has no page or particle family; its permitted primitive skill reference was read.
Target filenames below are relative to `packages/ui/src/components/ui/<family>/`.

This is a complete production-wrapper comparison for these 18 families. It is not a claim that
every primitive fixture, particle state, viewport, or assistive-technology interaction was rerun.
Fresh full particle reads covered Calendar and its date-picker consumers, Command, and all 29 Menu
and Context Menu importers. Matching Shards sources were followed where behavior needed evidence:
Autocomplete/Combobox refs, Menu/Context Menu popup refs, Input/Field relationships, and Toast
manager subscription lifetime. Calendar also used the installed MIT DayPicker selection source.

## Confirmed fixes and test gaps

- `calendar-timezone-toggle`: high confidence correctness defect. Rendering compared timezone-normalized
  dates while selection toggling compared raw external dates. Single and multiple browser regressions
  failed before the fix and now pass; the full focused Calendar set passes 39 tests. The adjacent
  test-only CodeQL comment-removal pattern was replaced with an anchored comment-only assertion.
- `command-dom-ref-forwarding`, `menu-dom-ref-forwarding`, `context-menu-dom-ref-forwarding`: medium
  severity, high confidence correctness/accessibility defects. Public inherited ref props did not
  write the mounted element back to callers. Three regressions failed with null refs, then passed
  after explicit bindings. They verify input focus and ref cleanup. The three families pass 16
  browser and 14 SSR tests, and the full workspace check reports zero errors and warnings.

These regressions fill specific blind spots in otherwise passing interaction suites: external
calendar dates near a timezone boundary and public DOM ref lifecycle. Default preview checks do
not prove cancellation, multiple selection, every keyboard path, dark mode, or mobile behavior.

## OTP documentation discrepancy

The pinned OTP registry, documentation, all nine particles, local Input/Field implementation, and
the rendered first-slot attributes were inspected. A root aria-label labels the group, while a
Field label labels the first input. The first input did not inherit a root aria-label in either
the port or the inspected upstream runtime. Therefore this was not classified as port behavior
drift. The upstream prose says the first slot should inherit the field label; the target prose
could also be read as promising root-label inheritance. The documentation now states that
distinction and labels the first slot explicitly in its root-only usage example. The existing OTP evidence already
records the actual group-only root-label behavior. No silent runtime divergence was introduced.
